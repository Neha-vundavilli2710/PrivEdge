# API Documentation

This is a **human-readable summary** of the PrivEdge REST API. It is not a replacement for the interactive documentation generated by FastAPI:

- **Swagger UI / OpenAPI:** <http://127.0.0.1:8000/docs>

The backend exposes **41 endpoints** (plus a root message at `GET /`), grouped below exactly as they exist in `backend/app/routes/`.

## Conventions

- **Base URL:** `http://127.0.0.1:8000` (the frontend uses `VITE_API_URL`).
- **Format:** JSON requests and responses; file uploads use `multipart/form-data`.
- **Authentication:** `Authorization: Bearer <JWT>` obtained from `/auth/login` or `/auth/register`.
- **Roles:** `USER`, `REVIEWER`, `ADMIN`. "Any user" means any authenticated account. Review endpoints accept `REVIEWER` or `ADMIN`; admin endpoints accept `ADMIN` only.
- **Role names in responses** are lower-case in `/auth/*` (`user`, `reviewer`, `admin`) and title-case in admin user lists (`User`, `Reviewer`, `Admin`).
- **Route values:** `edge`, `cloud`, `human`.

### Common status codes

| Code | Meaning |
|---|---|
| 200 / 201 / 204 | Success / created / no content |
| 400 | Business-rule violation (e.g. approving a review with no draft, wrong current password) |
| 401 | Missing, invalid or expired token; deactivated account; idle-session timeout |
| 403 | Authenticated but role not permitted (or login to a deactivated account) |
| 404 | Not found — also returned for another user's conversation |
| 409 | Conflict (duplicate email; review already completed or claimed by someone else) |
| 413 / 415 | Attachment too large / unsupported file type |
| 422 | Validation failure (Pydantic limits, unreadable attachment, failed response validation, sensitive Knowledge Base content) |

## 1. Health / system

| Method | Endpoint | Auth | Purpose |
|---|---|---|---|
| GET | `/` | none | Confirms the backend is running and points to `/docs`. |
| GET | `/health` | none | Returns `status`, `service`, `environment`. |

## 2. Authentication APIs — prefix `/auth`

| Method | Endpoint | Auth / role | Request | Response |
|---|---|---|---|---|
| POST | `/auth/register` | none | `name`, `email`, `password` (8–128 chars) | **201** `user`, `access_token`, `token_type`. Role is always `USER`. **409** if the email exists. |
| POST | `/auth/login` | none | `email`, `password` | `access_token`, `token_type`, `user`. **401** invalid credentials; **403** deactivated account. Failed and successful logins are audit-logged. |
| GET | `/auth/me` | any user | – | The current user's profile (`id`, `name`, `email`, `role`, `is_active`, `created_at`). |
| PATCH | `/auth/me` | any user | `name?`, `email?` | Updated profile. **409** if the email is taken. |
| POST | `/auth/change-password` | any user | `current_password`, `new_password` (8–128) | `{ok: true}`. **400** if the current password is wrong. |

## 3. Chat APIs

| Method | Endpoint | Auth / role | Request | Response |
|---|---|---|---|---|
| POST | `/chat` | any user | `message` (1–4000 chars), `conversation_id?` | Full pipeline result (see below). |
| POST | `/chat/attachment` | any user | multipart: `file` (`.txt`/`.md`/`.pdf`, ≤ 3 MB), `message?`, `conversation_id?` | Same result as `/chat`, plus `attachment_name`. **415** / **413** / **422** for bad files. |
| POST | `/analyze` | any user | `message` (1–4000) | **Dry run:** `route`, `reason`, `router_used`, `scores`, `decision`. Calls no model and stores nothing. |

**`/chat` response fields:** `conversation_id`, `message_id`, `response`, `attachment_name`, `route`, `reason`, `status` (`completed` / `pending_review` / `error`), `error`, `human_review`, `decision` (`privacy`, `sensitivity`, `complexity`, `risk`, `latency` as Low/Medium/High, `humanReview`, `reason`), `scores` (numeric scores, `human_required`, `contains_pii`, `domain`, `pii_types`, `categories`), `router_used` (`rule`/`ml`), `processing_time` (seconds; null for Human Review), `validator_issues`, `sources` (RAG document titles/scores).

If Edge AI or Cloud AI is unavailable the call still returns **200** with `error: true`, `status: "error"` and an explanatory `response`; the data is not sent to another path (see [Data flow](../architecture/data-flow.md)).

## 4. Conversation APIs

| Method | Endpoint | Auth / role | Request | Response |
|---|---|---|---|---|
| GET | `/conversations` | any user | query: `q?` (title search), `route?` (`edge`/`cloud`/`human`) | The caller's conversations: `id`, `title`, `route`, `status`, `msgs`, `preview`, `created_at`, `updated_at`. |
| GET | `/chat/history` | any user | – | Same list as `/conversations` (unfiltered). |
| GET | `/conversations/{id}` | owner | – | Conversation summary plus `messages[]`: `message_id`, `text`, `response`, `route`, `attachment_name`, `status`, `timestamp`, `decision`. **404** if not the owner. |
| PATCH | `/conversations/{id}` | owner | `title` | Updated summary. |
| DELETE | `/conversations/{id}` | owner | – | **204.** Deletes messages, routing logs and review rows of that conversation. |

## 5. Knowledge Base APIs

**User-facing — prefix `/knowledge`** (any user; only *Published* documents)

| Method | Endpoint | Request | Response |
|---|---|---|---|
| GET | `/knowledge` | query: `q?` (matches title, description **and content**), `type?` | List of `id`, `title`, `type`, `description`, `version`, `status`, `updated_at`. |
| GET | `/knowledge/{doc_id}` | – | Document including `content`. **404** if missing or not published. |

**Administration — prefix `/admin/knowledge`** (ADMIN)

| Method | Endpoint | Request | Response |
|---|---|---|---|
| GET | `/admin/knowledge` | – | All documents (every status). |
| GET | `/admin/knowledge/{doc_id}` | – | One document with content. |
| POST | `/admin/knowledge` | JSON: `title`, `doc_type`, `description`, `content`, `version`, `status` | **201** document. **422** if content looks sensitive. |
| POST | `/admin/knowledge/upload` | multipart: `file` (`.txt`/`.md`, ≤ 1 MB), `title`, `doc_type`, `description`, `version` | **201** document. **415/413/422** for bad or sensitive files. |
| PUT | `/admin/knowledge/{doc_id}` | same fields as create | Updated document (sensitivity screened again). |
| DELETE | `/admin/knowledge/{doc_id}` | – | Document with `status: "Archived"` (soft delete). |

## 6. Human Review APIs — prefix `/review` (REVIEWER or ADMIN)

| Method | Endpoint | Request | Response |
|---|---|---|---|
| GET | `/review/pending` | query: `q?` | Pending and in-review items: `id`, `code` (e.g. `REV-007`), `query` (**masked**, truncated), `status`, `risk`, `sensitivity`, `created_at`. |
| GET | `/review/history` | – | Completed reviews (reviewers see their own; admins see all) with `action`, `reviewer`, `completed_at`, `review_minutes`. |
| GET | `/review/stats` | – | Pending / in-review / completed counts, average review minutes, outcome split, 7-day activity, risk distribution. |
| GET | `/review/{id}` | – | Item detail: masked `query_full`, `user_ref` (`USR-xxxxx`), masked `ai_draft`, `has_draft`, `analysis` (levels, domain, reason, scores). Audit-logged. |
| POST | `/review/{id}/claim` | – | Marks the item `IN_REVIEW` for the caller. **409** if completed or claimed by another reviewer. |
| POST | `/review/{id}` | `action` = `approve` \| `modify` \| `reject`, `comment?`, `final_response?` (required for `modify`) | The item plus `final_response`. **400** approve without draft / modify without text; **409** already completed; **422** response failed validation. Notifies the requesting user. |

## 7. Dashboard / analytics APIs

| Method | Endpoint | Auth / role | Response |
|---|---|---|---|
| GET | `/dashboard/statistics` | any user | The caller's **own** activity: totals and route counts/percentages, average processing time, privacy/sensitivity/complexity/risk distributions, 7-day activity, hourly volume and response time, conversation count, pending reviews, recent conversations. |

## 8. Admin APIs — prefix `/admin` (ADMIN)

| Method | Endpoint | Request | Response |
|---|---|---|---|
| GET | `/admin/statistics` | – | System-wide analytics plus user count, review statistics and recent audit events. |
| GET | `/admin/routing-analytics` | query: `days` (1–90, default 7) | Route distribution, score distributions, daily trend, router usage, average time per route, share of sensitive queries kept off Cloud. |
| GET | `/admin/review-monitoring` | – | Review statistics plus the ten most recent review events. |
| GET | `/admin/users` | query: `q?`, `role?`, `status?` | User rows: `id`, `code`, `name`, `email`, `role`, `status`, `joined`, `queries`. |
| GET | `/admin/users/{user_id}` | – | User detail with route counts, conversation count and recent conversation titles. |
| PATCH | `/admin/users/{user_id}` | `role?` (`USER`/`REVIEWER`/`ADMIN`), `is_active?` | Updated user. **400** if an admin tries to deactivate or demote themself. |
| GET | `/admin/logs` | query: `q?`, `route?`, `limit?` (1–1000, default 200) | Query log rows: id (`Q-…`), timestamp, levels, route, router, reason, processing time, scores. **No message content.** |
| GET | `/admin/monitoring` | – | Live checks: API, Database, Cloud AI (Gemini), Edge AI (Ollama), RAG index — each with status (`Operational` / `Warning` / `Down`), response time and detail; plus recent events and the router mode. |
| GET | `/admin/settings` | – | `settings` (groups `routing`, `security`, `ai`, `notifs`), `enforced` and `not_enforced` key lists. |
| PUT | `/admin/settings` | partial settings object | Saved settings (merged with defaults). Audit-logged. |

## 9. Notification APIs — prefix `/notifications` (any user)

| Method | Endpoint | Response |
|---|---|---|
| GET | `/notifications` | `items[]` (`id`, `type`, `icon`, `title`, `message`, `read`, `created_at`) — personal notifications plus broadcasts for the caller's role; `unread` count. |
| POST | `/notifications/read-all` | `{marked: n}` — marks everything visible to the caller as read. |

## Example — a chat request

```http
POST /chat
Authorization: Bearer <token>
Content-Type: application/json

{ "message": "Analyze this confidential employee salary report.", "conversation_id": null }
```

The shape of a response (abridged; the values shown are illustrative):

```json
{
  "conversation_id": 12,
  "response": "…processed locally by Edge AI…",
  "route": "edge",
  "reason": "High privacy and data sensitivity detected, so the raw query is processed locally by Edge AI and is not sent to the cloud.",
  "status": "completed",
  "human_review": false,
  "decision": { "privacy": "High", "sensitivity": "High", "complexity": "Medium", "risk": "Low", "latency": "Low", "humanReview": false },
  "router_used": "rule"
}
```
